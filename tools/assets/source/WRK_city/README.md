# Высотки Воркенсберга и Стеландера

Новые самостоятельные модели для A-Discord / Hearts of Iron IV. Устаревшие
`skyscraper1–3.mesh`, их отдельные diffuse-текстуры и регистрации удалены.
Исходные пользовательские cityblock, Congress и Unity Tower mesh/DDS сохранены.
Городские потребители переведены на новые entity в собственном namespace
`ADISCORD_city`. Файлы WAH не используются.

## Состав

- Воркенсберг: три силуэта высоток высотой 2.93–3.67 единицы над основанием,
  три квартала по семь зданий с дворами, переходами и техническими крышами.
- Стеландер: три высотных комплекса, 3.09–4.31 единицы над основанием,
  голубое, бронзовое и серебристое стекло, мосты между башнями.
- Четыре статичных рекламных изображения: связь, напиток, транспорт, жильё.
  Псевдонадписи намеренно неразборчивы. Это светящиеся поверхности, а не видео.
- Девять native `.mesh`, 18 общих DDS BC3 с полными mip chains. На модель
  1012–2194 треугольников, 5–7 материалов. Shader `PdxMeshAdvancedSnow`.
- Нормали используют HOI4 G/A; B у экранов содержит маску ночного свечения.
  Diffuse непрозрачный. Альфа не используется как отверстия или стеклянная прозрачность.

## Подключение к карте

Воркенсберг содержит 11 отдельных высоток и 12 крупных кварталов. Размещение
учитывает уклон, береговые линии, соседние объекты и свободную площадь Unity Tower.

В Стеландере размещены пять отдельных высотных комплексов.
Широкие основания перенесены с береговых или слишком крутых точек на ближайшие
подходящие площадки. Координаты исходных точек и итоговое размещение доступны
в `existing_placement.json` и `placement_report.json`.

Ванильная процедурная застройка сохранена: новые здания не подставляются
в citygroup и не меняют маску `map/cities.bmp` или реестр `map/cities.txt`.

Семь исходных объектов промышленности и Congress привязаны к рельефу без
изменения их mesh, DDS, масштаба и поворота. Поиск опорной площадки проверяет
проекцию фактической геометрии целиком, принадлежность исходному штату и
отступы от соседних объектов. Прочие ambient объекты и регистрации сохранены.

## Воспроизведение

Из корня мода:

```powershell
python tools/assets/source/WRK_city/prepare_materials.py
& 'D:\steam\steamapps\common\Blender\blender.exe' --background --threads 2 --python-exit-code 1 --python tools/assets/source/WRK_city/build_city.py
python tools/assets/source/WRK_city/package_city.py
python tools/assets/source/WRK_city/package_city.py --apply
python tools/assets/source/WRK_city/package_city.py --check
python tools/assets/source/WRK_city/verify_city.py
node tools/assets/source/WRK_city/verify_jorodox.cjs 'C:\Users\Admin\AppData\Local\Google\Chrome\User Data\Default\Extensions\pmhbboeiannanamjandkhiakpaaoecoo\0.8.1_0'
python -B tools/validate_tc.py --limit 300
git diff --check
```

Сохранён авторский обход граней: пересчёт normal на разорванных UV-островах
разворачивал отдельные стены внутрь. Проверка `check_face_orientation.py`
с аргументом `--native` сравнивает каждый треугольник после native roundtrip
с исходным направлением. Все девять моделей прошли.
Развёртка стен разбита на геометрические плитки с UV 0..1: окна больше
не зависят от RepeatWrapping, которого нет в DDS loader JoroDox.

Геометрия проверяется до рендера и затем повторно импортируется из native mesh.
`City_native_preview.png` — рендер этого повторного импорта в Blender.
`build_report.json`, `verification_report.json`, `jorodox_report.json` содержат
результаты проверок. `verify_jorodox.cjs` проверяет данные, без рендера.
В `jorodox_visual/` находятся 18 настоящих WebGL кадров (обе стороны каждой
модели) из локального стенда с неизменёнными установленными библиотеками
JoroDox 0.8.1. Включён FrontSide; проверяются хеши mesh и отсутствие ошибок
WebGL. Стенд: `python tools/assets/source/jorodox_preview_server.py`, затем
`http://127.0.0.1:8767/?batch=city`. Он использует Phong fallback, поэтому не
подтверждает native snow/lighting HOI4. Проверка снимков:
`python tools/assets/source/verify_jorodox_visual.py`.

Три исходные текстуры стены/кровли/окон Unity Tower используются только для чтения.
Новые варианты стекла и рекламы получены через built-in image_gen; точные prompts
и имена исходных PNG сохранены в `imagegen_source.json` и
`advertisements_source.json`. При упаковке меняются только формат, mip chains
и UV-разбиение атласов.

## Проверка в игре

Ambient Y — смещение относительно высоты земли в центре объекта. Для новых
зданий генератор ставит верх площадки над максимальной высотой рельефа под
основанием, а нижнюю грань заглубляет. Для исходных объектов используется
минимальная высота внутри проекции геометрии; допустимый уклон и погружение
ограничены размером модели. Абсолютную высоту heightmap повторно прибавлять нельзя.

При изменении геометрии или размещения нужен холодный запуск HOI4:

1. Проверить высоту оснований относительно земли, в том числе на краях площадок.
2. Осмотреть Воркенсберг и Фаду вблизи и на рабочем масштабе камеры: основания,
   пересечения, улицы, Congress, Unity Tower, culling.
3. Проверить ванильную процедурную застройку рядом с отдельными объектами
   и читаемость рекламы днём/ночью.
4. Проверить анимацию частичного разрушения Unity Tower и сохранение руин после
   загрузки отдельно по инструкции `../WRK_unity_tower/README.md`.

Результаты отдельной проверки в движке хранятся в отчёте
`../infantry_weapons_3d/verification_report.json`. Проверка файлов и WebGL
сама по себе не подтверждает размещение на рельефе и переходы игрового entity.
