# Проект «Цепелин»

Нейтральный прототип воздушного линкора без государственной символики.
Огромная жёсткая оболочка, нижняя бронированная палуба, шесть трёхорудийных
башен и шесть винтовых двигателей. Размеры художественные, не инженерный расчёт.

## Файлы

- `ADISCORD_zeppelin.blend` — редактируемая модель, упакованные материалы,
  каркас из 19 костей, три действия и освещение для просмотра.
- `ADISCORD_zeppelin.mesh` — нативный экспорт с UV, жёсткими весами,
  восемнадцатью дульными локаторами и шестью точками выхлопа.
- `ADISCORD_zeppelin_idle.anim` — зависание и вращение винтов.
- `ADISCORD_zeppelin_move.anim` — лёгкий наклон и ускоренное вращение винтов.
- `ADISCORD_zeppelin_attack.anim` — зависание, винты и отдача стволов.
- `ADISCORD_zeppelin_{diffuse,normal,specular}.dds` — атлас 1024×1024,
  DXT5 с mip-уровнями; normal содержит нейтральные нормали.
- `ADISCORD_zeppelin_{preview,side}.png` — рендеры обратно импортированного `.mesh`.
- `verification.json` — геометрия, проверки анимаций, контрольные суммы.

Модель зарегистрирована в `gfx/entities/ADISCORD_zeppelin.gfx` и
`gfx/entities/ADISCORD_zeppelin.asset`, масштаб 0,24. Техника и подразделение
находятся в существующих `ADISCORD_air_equipment.txt` и `ADISCORD_land_units.txt`.
Полноценная исследовательская ветка спецпроекта и серийное производство не открыты.

## Испытание за VAL

В режиме `-debug` игроку VAL доступно решение «Создать воздушный линкор
„Цепелин“» в существующей категории DEBUG. Бесплатно создаёт в принадлежащем
VAL и контролируемом столичном регионе одно полностью укомплектованное соединение:
один корпус, 400 человек. Повторяется через сутки. ИИ решение не использует.
Шаблон `Kefreyt Zeppelin Trial` создаётся один раз, заблокирован для изменений
и напрямую использует `ADISCORD_zeppelin_entity`.

Это наземное соединение с парящей моделью: оно участвует в наземном бою,
подчиняется сухопутным маршрутам, снабжению и ограничениям передвижения.
Численные параметры испытательные; серийного пополнения корпусов нет.

## Контракт будущего наземного юнита

Состояния `idle`, `move`, `attack` — самостоятельные двухсекундные циклы
с частотой 30 кадров/с. Корень остаётся на месте; перемещение между провинциями
должно задаваться игровым юнитом. Геометрия поднята над его корнем.
Отступление использует `move`, обучение — `idle`, оборона и поддержка атаки —
`attack`. Состояние гибели временно использует `idle` до удаления модели
движком; отдельной анимации разрушения нет.

Арматура: `root`, шесть костей башен, шесть дочерних костей отдачи,
шесть костей винтов. `*_muzzle_1..3` следуют за стволами. Урон задаётся
техникой; `.anim` отвечает только за движение.

## Частицы

На отметке 0,5 секунды каждого боевого цикла вспыхивают все 18 стволов.
Дым запускается у центрального ствола каждой из шести башен. Дульные локаторы
ориентированы вдоль соответствующих стволов. Все шесть башен направлены
вперёд, к носу корабля; отдача у всех орудий идёт назад.
Шесть отдельных точек на неподвижных гондолах выпускают лёгкий выхлоп.
Эмиттер выхлопа создаётся один раз на состояние и прекращается при его смене;
состояние гибели его не запускает. Короткие вспышки и дым завершают свой цикл.

Определения в `gfx/particles/ADISCORD_zeppelin.asset` и регистрации в
`gfx/entities/ADISCORD_zeppelin.gfx` принадлежат генератору модели.
Используются штатные текстуры `glow.dds` и `cloud_2.dds` без копирования.
Каждый эмиттер ограничен 4 или 12 частицами; отдельной пыли у земли нет.

## Звук

Исходные записи находятся в `audio/`. Генератор проверяет их SHA-256 и
собирает четыре монофонических WAV, PCM16, 44100 Гц в `sound/zeppelin/`.
На стоянке звучит более тихий цикл винтов с понижением тона примерно на
4,75 полутона; в движении — примерно на 3 полутона. Низкие частоты слегка
усилены, граница цикла сглажена перекрытием.

При входе в `move` или `retreat` постоянный цикл включается сразу с коротким
плавным входом. Поверх него один раз звучит более тихий разгон длиной 1,6 секунды.
Это событие состояния модели: повторный вход в движение снова запускает разгон.
В `attack`, `support_attack` и `defend` одиночный выстрел запускается на
0,5 секунды каждого двухсекундного цикла — в начале отдачи стволов.
Хвост выстрела может перекрываться со следующим залпом.

Регистрация `sound/adiscord_zeppelin.asset` использует категорию `Battle`,
пространственное затухание и ограничение четырьмя одновременными экземплярами
каждого эффекта. В состоянии гибели новые звуки не запускаются.

Короткий общий отклик `vehicle_move` при отдаче приказа сохраняется:
движок выбирает его для моторизованного соединения независимо от звуков
анимации модели. Определение общего отклика не переопределяется.

## Сборка

В корне репозитория:

```powershell
python -B -m tools.assets.source.build_zeppelin --check
python -B -m tools.assets.source.build_zeppelin --apply
& 'D:/steam/steamapps/common/Blender/blender.exe' --background --factory-startup --python tools/assets/source/build_zeppelin.py -- --build
python -B -m tools.assets.source.build_zeppelin --check
python -B -m tools.assets.source.build_zeppelin --install --check
python -B -m tools.assets.source.build_zeppelin --install --apply
python -B -m tools.assets.source.build_zeppelin --install --check
```

Первый `--check` показывает отсутствующие или изменившиеся текстуры.
`--apply` записывает только текстуры в эту папку. `--build` создаёт исходник,
нативные файлы, проверяет обратный импорт и рендерит два ракурса.
Последний `--check` сверяет текстуры, исходный генератор и хеши готовых файлов.
`--install --check` показывает расхождения игрового пакета; `--install --apply`
записывает принадлежащие генератору модели, регистрации, иконки, звуки и частицы.
Нужны Blender с установленным IO PDX Mesh, Python с Pillow, NumPy, SciPy
и FFmpeg в PATH для декодирования аудиоисточников.
Проверка Blender не подтверждает поведение в HOI4. Для проверки в игре нужен
полный перезапуск с финальными файлами и новая кампания VAL в режиме DEBUG.
