# Подготовка обновления A-Discord к релизу

Этот чек-лист нужен для обновлений, которые меняют игровые скрипты, фокусы,
условия доступности или интерфейс. Он разделяет статическую проверку исходников
и доказательство поведения в свежей кампании.

## 1. Зафиксировать исходное состояние

Перед началом работы сохранить вывод:

```powershell
git status --short
git diff --stat
git diff --check
```

Чужие незавершённые изменения не откатывать и не включать в релизный список.
После правок сравнить `git diff --name-only` с этим исходным списком.

## 2. Проверить код и локализацию

Gameplay-файлы (`.txt`) должны быть UTF-8 без BOM. Русская локализация (`.yml`)
должна оставаться UTF-8 с BOM, а значение каждой строки - физически одной
строкой; переносы записываются как `\n\n`.

Для этой ветки достаточно начать с узких тестов:

```powershell
$env:PYTHONIOENCODING = 'utf-8'
python -B -m unittest tools.tests.test_validate_adiscord_val_rework
python -B -m tools.validators.validate_adiscord_val_rework
```

Затем выполнить общий статический проход:

```powershell
$env:PYTHONIOENCODING = 'utf-8'
python -B tools/validate_tc.py --limit 300
git diff --check
```

Если менялся генератор или его выход, сначала запустить dry-run/`--check`,
затем явный `--apply`, после чего ещё раз `--check` и проверить идемпотентность
вторым запуском. Сгенерированные файлы вручную не редактировать.

## 3. Проверить ветку Кефрейта

Статическая проверка должна подтверждать последовательность VAL:

1. `VAL_The_Contract_State` -> `VAL_The_Weaponry_Baron` ->
   `VAL_One_Ledger_One_Banner` открывают базовую систему контрактов.
2. Северные курсы `VAL_Trading_Partners` и `VAL_October_Of_2160`
   взаимоисключающие.
3. `VAL_Contracts_Outlive_Kings` ведёт через `VAL_frontier_conference` к
   логистике, комиссарам и пограничному договору.
4. Хартия и расширение требуют своих условий по регионам, войнам и
   контрактной администрации; новый scripted trigger не должен менять
   результат этих проверок.

При изменении пререквизитов проверять обе северные ветки и послевоенный маршрут.
Обычная дипломатия не является запасным путём: война и союз запускаются только
существующими scripted focus, decision и event-маршрутами.

## 4. Доказать загрузку в игре

Перед запуском записать SHA-256 изменённых загружаемых файлов:

```powershell
$files = @(
  'common/national_focus/ADISCORD_national_focus_VAL.txt',
  'common/scripted_triggers/ADISCORD_VAL_rework_triggers.txt',
  'localisation/english/ADISCORD_VAL_decisions_l_english.yml',
  'localisation/russian/ADISCORD_VAL_decisions_l_russian.yml'
)
$files | ForEach-Object {
  Get-FileHash -Algorithm SHA256 -LiteralPath $_
}
```

Полностью перезапустить Hearts of Iron IV с этими файлами и открыть свежую
кампанию. Проверить не только доступность фокусов, но и реальный переход:

- стартовый гайд показывает порядок базовой, северной и послевоенной веток;
- фокусы экспансии показывают понятные причины блокировки и не открываются
  раньше контроля нужных регионов;
- принятие оружейной сделки не оставляет проданные запасы для своей армии;
- послевоенная администрация и северные решения действительно открываются
  после завершения требуемой кампании;
- в `error.log` нет ошибок загрузки фокусов, scripted triggers, локализации и
  интерфейса.

Статический тест или успешный код валидатора не заменяет эту проверку. После
горячей перезагрузки открытого события результат не считать доказательством:
нужен полный перезапуск и новая кампания.

## 5. Сформировать релизный набор

Перед публикацией выполнить:

```powershell
git diff --name-only
git diff --stat
git diff --check
```

В список должны попасть только проверенные исходники, локализация и нужные
ассеты. Локальную копию `A-Discord-release` обновлять и сверять по SHA-256
только после отдельного разрешения на копирование; Workshop не является
источником проверки. Для каждой скопированной пары файл должен иметь одинаковый
хеш, а итоговый список файлов - совпадать с проверенным `git diff`.

В итоговой записи релиза сохранить:

- commit или архивный идентификатор исходников;
- список изменённых файлов и их SHA-256;
- результаты узких тестов и `validate_tc.py`;
- дату свежего запуска и краткий результат кампании;
- известные ограничения, которые статикой не доказываются.

Если любой пункт runtime-проверки не выполнен, обновление считать готовым к
внутреннему тесту, но не к публичному релизу.

## 6. Совместимость с HOI4 1.19.4

Источник требований: [официальный патчноут 1.19.4, checksum a783](https://store.steampowered.com/news/app/394360/view/684142629662760619).
Доступный исходник игры в `Z:/SteamLibrary/steamapps/common/Hearts of Iron IV/`
имеет `rawVersion = 1.19.3.0` в `launcher-settings.json`. До получения 1.19.4
перенос интерфейса и проверка в новом движке остаются незавершёнными.
`supported_version="1.19.*"` уже допускает новый патч, но не доказывает
совместимость. Поле `version` обозначает версию мода, а не установленной игры.

### Доктрины и боевые данные

Трек `ADISCORD_land_networked_operations` использует `category_army` для
получения опыта оперативного управления. Это охватывает также боевых роботов,
линейную артиллерию и дирижабли. Источник находится в
`tools/builders/build_adiscord_doctrine_system.py`, результат - в
`common/doctrines/tracks/ADISCORD_doctrine_tracks.txt`. Коэффициент опыта 0.8,
стоимость ступеней и награды школ сохраняются.

Тест `DoctrineContractTests.test_every_army_unit_can_earn_operations_mastery`
проверяет охват реальных армейских подразделений в генераторе и загружаемом
файле. Команды проверки:

```powershell
python -B -m unittest tools.tests.test_validate_adiscord_technology_contracts.DoctrineContractTests
python -B -m tools.builders.build_adiscord_doctrine_system --check
```

Ванильные изменения HP танков, шасси, модулей, моторизованной пехоты и наград
доктрин не являются готовыми значениями для собственного состава A-Discord.
Мод заменяет технологии, подразделения, оборудование и доктрины. Его боевые
платформы и механизированная пехота имеют собственные характеристики, поэтому
перенос этих чисел требует отдельного расчёта баланса. Новые блоки оборудования
`scaled_by_reliability`, `module_add_stats_multiplier` и
`module_multiply_stats_multiplier` необязательны; вводить их без проверки
синтаксиса и результата на движке 1.19.4 нельзя.

### Интерфейс после установки обновления

Сравнить следующие переопределения с исходниками 1.19.4. Названия новых native
виджетов, их типы, родителей и GFX брать из файлов игры. Патчноут не содержит
контрактов интерфейса, по которым можно безопасно восстановить эти элементы.

| Изменение 1.19.4 | Файлы мода для сверки | Владелец правки |
| --- | --- | --- |
| Мини-карта фокусов и расположение фильтров | `interface/nationalfocusview.gui` | `build_adiscord_focus_ui_assets.py` |
| Горячие клавиши исследований, выбор следующего слота, отказ от ограниченного бонуса | `interface/countrytechnologyview.gui` | `build_adiscord_technology_ui_assets.py`; проверить также выходы `build_adiscord_technology_system.py` |
| Очередь улучшений разведки, таймер операций, фильтр недоступных операций, флаги оперативников | `interface/countryintelligenceagencyview.gui`, `interface/operative.gui`, `interface/operativeleader.gui` | `build_adiscord_intelligence_ui_assets.py` |
| Автоматическая торговля, приоритет ресурсов и импорт через Shift | `interface/countrytradeview.gui`, `interface/countryproductionlineview.gui`, `interface/topbar.gui` | Ручные GUI; сохранить ресурсы и экономику мода |
| Приоритеты ремонта и исправление прокрутки | `interface/countryconstructionsview.gui` | Ручной GUI |
| Автоматические дипломатические ответы и отзыв добровольцев | `interface/countrydiplomacyview.gui`; проверить связанные уведомления игры | Ручной GUI; сохранить запреты обычной войны и вступления в союзы |
| Фильтры политических советников | `interface/countrypoliticsview.gui`; проверить связанное окно выбора идей | Ручной GUI и существующая система кадров |
| Удаление лишних настроек автоматизации рынка | `interface/international_market/requestautomationoptionswindow.gui` и другие GUI рынка | `build_adiscord_market_ui_assets.py` |

В генераторе разведки `VANILLA_FILES` содержит SHA-256 исходников. Новый хеш
принимать только после сравнения изменений; не отключать проверку ради сборки.
Для каждого изменённого генератора выполнить проверку, затем `--apply`, затем
повторную проверку и второй запуск с сопоставлением хешей выходов. Владельцы
перечислены в `tools/data/generated_output_owners.json`.

Обновления движка, включая расчёт захваченного оборудования, резервирование
экипажей кораблей при производстве, переменные областей и исправление
`hidden_modifier` советников, поступают с самой игрой. Не воспроизводить их
периодическими скриптами. Новые необязательные параметры `set_major` и
пограничных войн применять только при необходимости конкретного сценария,
с подтверждённым синтаксисом 1.19.4.

После переноса записать хеши загружаемых файлов и полностью перезапустить игру.
В новой кампании проверить мини-карту и фильтры фокусов, оба способа запуска
исследования, очередь разведки с отменой, торговлю всеми ресурсами мода,
приоритеты ремонта, выбор советника, добровольцев и автоматические ответы.
Отдельно проверить начисление оперативного опыта в бою подразделениям,
которые используют только общую армейскую категорию. Сверить свежий `error.log`
и экранные результаты; статическая проверка не подтверждает работу этих UI.
